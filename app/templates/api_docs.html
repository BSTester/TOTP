API REFERENCE

接口文档

仅展示动态密码获取与查询接口。所有接口都需要在请求头中传入 X-API-Key。

风险提醒：为支持通过接口二次获取验证码，本项目会在服务端保存必要的 TOTP 配置信息（密钥会加密存储）。请仅在你信任并可控的环境中使用，妥善保管 API Key；因使用本项目或配置不当造成的风险与损失，由使用者自行承担，本项目不承担责任。

返回控制台

一次生成动态密码

适合临时取码，不落库；支持 Base32 密钥、otpauth URI 和二维码图片。

POST /api/totp/code-from-source

JSON 请求。传 base32_secret 或 otpauth_uri 其中一个即可。

curl -X POST http://127.0.0.1:8010/api/totp/code-from-source \
  -H "Content-Type: application/json" \
  -H "X-API-Key: tk_xxx" \
  -d '{"base32_secret":"JBSW Y3DP EHPK 3PXP"}'
curl -X POST http://127.0.0.1:8010/api/totp/code-from-source \
  -H "Content-Type: application/json" \
  -H "X-API-Key: tk_xxx" \
  -d '{"otpauth_uri":"otpauth://totp/Demo?secret=JBSWY3DPEHPK3PXP&issuer=Demo"}'
POST /api/totp/code-from-qrcode

multipart 上传二维码图片。图片只用于本次识别，不会持久化保存。

curl -X POST http://127.0.0.1:8010/api/totp/code-from-qrcode \
  -H "X-API-Key: tk_xxx" \
  -F "file=@qrcode.png"

响应示例

{
  "code": "123456",
  "period": 30,
  "remaining": 18,
  "persisted": false,
  "unique_id": null
}

查询动态密码

先在控制台生成记录，拿到 8 位唯一标识后，可通过接口实时查询当前验证码。

GET /api/totp/code/{唯一标识} 
curl -X GET "http://127.0.0.1:8010/api/totp/code/a1b2c3d4" \
  -H "X-API-Key: tk_xxx"

响应示例

{
  "id": "totp_xxxxxx",
  "unique_id": "a1b2c3d4",
  "issuer": "",
  "account": "",
  "code": "123456",
  "period": 30,
  "remaining": 18
}
POST /api/totp/codes/batch

批量查询最多 200 个唯一标识；不存在的记录会在对应项返回中文错误。

curl -X POST http://127.0.0.1:8010/api/totp/codes/batch \
  -H "Content-Type: application/json" \
  -H "X-API-Key: tk_xxx" \
  -d '{"ids":["a1b2c3d4","x9y8z7w6"]}'

字段说明

字段说明
base32_secretBase32 手动密钥。支持空格、小写和横线分组，服务端会自动规范化。
otpauth_uri标准 TOTP 链接，通常从二维码中解析得到。
code当前动态验证码。
remaining当前验证码剩余有效秒数。
unique_id控制台生成记录后的 8 位唯一标识，用于后续查询。
